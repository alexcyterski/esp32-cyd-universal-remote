# PULSE — E32R28T IR remote

A compact, offline touchscreen remote for the **ELEGOO/LCDWiki E32R28T**, with smooth Inter typography, a square-edged charcoal interface, warm orange accents, and large touch targets. No SD card, network account, Wi-Fi setup, or external server is needed.

## Start here

1. Read `HARDWARE_VALIDATION.md` and choose the matching full/simple sheet in `hardware/`. Read `INSTALL.md` to flash that profile.
2. On first boot, tap the four calibration targets with a stylus. The last target validates the first three. If calibration fails, the sequence starts again.
3. Open **All**, choose a device type, manufacturer, then action. Model names appear beneath actions. Open **Emit** to test the action, then **Add favorite**.
4. Open **Listen / Emit → Listen**, aim an existing remote at the IR receiver, and press one button briefly. Review/test the capture, then **Save code** and enter one short description.

`preview/screens.png` shows screens generated by the same layout code and Inter glyph bitmaps used on the device. Panel color reproduction can differ slightly. Example favorites in the preview are demonstration data; the device starts with an empty Favorites list.

## Three tabs

| Tab | Behavior |
| --- | --- |
| Favorites | Up to 64 catalog actions. Tap to transmit immediately; hold for at least 650 ms to view details or remove a favorite. Context identifies the manufacturer and device type. |
| All | Every action in the **bundled catalog**, arranged by device type → manufacturer → action. Model names distinguish variants. Three large rows per page, with explicit previous/next buttons. Details show protocol and code, allow transmission, and toggle a favorite. |
| Listen / Emit | Listen for one code, enter a code manually, or open the 24 saved-code slots. Tap a saved entry to send it; hold to rename or delete it. |

Main action/list targets are 44–54 px tall. Keyboard keys are 43 × 38 px; a stylus is useful for text. Navigation stays at the bottom. An orange line flashes for 400 ms after a send. Open **Listen / Emit → Eco** to select a power mode. The first waking touch restores the screen without firing an action.

## Power modes

Every screen includes a battery voltage readout (for example, **3.87 V**) and a small level bar. The bar scales linearly from **3.00 V = empty** to **4.20 V = full**, clamping outside that range; the voltage itself remains the measured value. At or below 3.00 V the readout turns orange. Invalid readings show `--.-- V`. Both profiles sample the onboard GPIO34 divider every five seconds while awake, pausing during IR learning, and refresh after sending or waking. Battery updates do not reset the inactivity timer.

These are display endpoints, not charging or shutdown controls. The full build's transmit guard uses its existing 3.40 V trip / 3.55 V recovery thresholds. The ADC reads the board's BAT+ node, so USB charger voltage may appear even without a connected battery. Compare with a meter and adjust `board::BATTERY_SCALE` if needed.

| Mode | Active backlight | Inactivity behavior |
| --- | --- | --- |
| Default | 100% | Backlight off after 60 seconds; ESP32 remains awake. |
| Power saving | Approximately 50% PWM drive | After 20 seconds, backlight off, display controller asleep, and ESP32 in light sleep. |

The mode is saved in flash and applies to either hardware build. A new installation starts in Default mode. Touch activity and incoming USB data reset the inactivity timer. Learning prevents sleep; sending and saving complete before sleep can begin. The first touch after either mode's timeout is consumed until the finger is released.

Light sleep retains the current page, an unsaved capture, and text being edited, so waking does not reboot or recalibrate. Wake is driven by the onboard touch controller's active-low IRQ on GPIO36; no extra wire is required on the E32R28T. The CPU and display resume before the backlight comes on. Wi-Fi and Bluetooth are never started. IR carrier settings and the full build's voltage guard apply in both power modes.

When Power saving is asleep, **tap the screen before sending USB commands**. USB serial and IR reception are not wake sources. Deep sleep is not used. The board's regulator, charger, touch controller and external receiver still consume power; 50% backlight drive does not mean 50% total power. Sleep current, brightness and wake reliability require measurement on the assembled remote. See `POWER_SAVING.md` for implementation details and the hardware test sequence.

Theme: background `#0B0C0F`, panels `#191B20`, orange `#FF8A36`, primary text `#F3F2EF`. Inter is embedded in flash as 4-bit antialiased glyphs: 23 px semibold headings, 15 px medium buttons, and 11 px regular context. Text is fitted by measured pixel width. `tools/build_fonts.py` regenerates the glyphs from the included OFL font; no font download or filesystem is needed on the device.

## Catalog coverage

The bundled catalog includes **2,978 actions, 28 device types, and 88 manufacturers** in a 254,323-byte flash catalog. “All” means all supported entries in this bundled snapshot; no complete database of every remote in existence is available here. Compatibility must be tested against your own equipment. Manufacturer names do not guarantee that a code works with every model.

The source is [Flipper-IRDB](https://github.com/Lucaslhm/Flipper-IRDB), revision `d126fb1b6f1e114c52b4a8c19839ea65e3a9c24d`. Its license explicitly excludes material predating the CC0 change. This package conservatively imports only paths absent at the licensing cutoff `2319685f2cbf0cd3f809609622cade14d24fb819`. It excludes unsupported protocols and captures outside the timing limits. `assets/catalog_report.json` records the selection and exclusions; `catalog_index.json` lists every included action. The database is not downloaded at runtime.

Rebuild that snapshot with Python 3 and Git:

```sh
git clone https://github.com/Lucaslhm/Flipper-IRDB.git ../Flipper-IRDB
git -C ../Flipper-IRDB checkout d126fb1b6f1e114c52b4a8c19839ea65e3a9c24d
python tools/build_catalog.py ../Flipper-IRDB --output assets
```

Rebuild firmware after changing the catalog. Favorites use stable IDs; removed entries can be removed from Favorites with a hold. Adding a learned/manual code uses the 24 saved slots rather than changing the compiled catalog.

## Manual codes and capture limits

Supported text formats use **IRremoteESP8266 send-value bit ordering**, not arbitrary values copied from another library:

```text
NEC:32:20DF10EF
SAMSUNG:32:E0E040BF
SONY:12:A90
RC5:12:00C
RC6:20:0000C
RAW:38:9000,4500,560,560,560
```

These are syntax examples; the short RAW example is not a complete appliance command. Decimal bits/kHz, hexadecimal decoded values, decimal microseconds for RAW. RAW alternates **mark, space, mark, space…**, beginning with an LED-on mark. NEC and Samsung accept 32 bits; Sony 12/15/20; RC5 12; RC6 mode 0, 20. RC5 and RC6 maintain independent toggle state; each changes on a send of that protocol. Sony sends the initial frame plus two repeats. Other decoded protocols and extended variants are captured as RAW when they fit.

RAW permits 30–60 kHz, 3–1,024 durations, each 1–65,535 µs, and at most 1.5 seconds total. Incoming captures end after a 50 ms silence; longer gaps may split a multi-frame command. Long or unsupported stateful air-conditioner messages may not fit. A VS1838B reports demodulated timing, **not carrier frequency**: unrecognized captures assume 38 kHz and say so. It cannot faithfully learn every carrier, and replay is not guaranteed for rolling codes or unusual multi-frame protocols. All send paths use the selected firmware profile's nominal carrier duty: 33% for full, 50% for simple. Actual timing requires measurement on hardware.

Listen waits up to 12 seconds. Repeat-only packets and overflowing captures are not saved. Test a capture before saving. Each of the 24 slots holds one code and **one description field**, up to 28 uppercase ASCII characters, digits, spaces, and the keyboard's punctuation. Full storage asks you to delete a slot first; it never silently overwrites a slot. Saving and favorite changes persist immediately in onboard NVS.

Existing eight-slot saves load automatically, with 16 additional empty slots. The first edit migrates storage to separate slot/Favorites records, retaining the original data until migration finishes. Each subsequent edit writes only its changed record, allowing 24 maximum-length RAW codes within the existing 64 KB NVS partition. The partition map and touch/power preferences are preserved. Older firmware cannot read the migrated records.

For long RAW input, use a serial terminal at **115200 baud**, newline ending, and send:

```text
CODE NEC:32:20DF10EF
```

This imports a code into the review screen; it does not automatically transmit. **View code**, capture, and transmission also print the full text over USB. Maximum input is 6,200 characters. USB import is the practical route for long raw codes.

Send `TXTEST` followed by a newline to generate six 50 ms, 38 kHz carrier bursts over approximately half a second. This uses the normal transmit path and selected profile, but does not represent an appliance command. Use it to check GPIO27, LED polarity, and carrier modulation with a scope, logic analyzer, nearby IR receiver, or an IR-sensitive camera. The full profile still applies its battery guard.

## Hardware configuration

| Function | GPIO / connector |
| --- | --- |
| IR transmit, active high | GPIO27, P3 pin 4 |
| IR receiver output, 3.3 V logic | GPIO35, P4 pin 2 |
| Receiver power / ground | P4 pin 1, 3.3 V / P4 pin 4, GND |
| TFT SPI | SCLK14, MOSI13, MISO12, CS15, DC2; hardware reset |
| TFT backlight | GPIO21 |
| Resistive touch SPI | CLK25, MOSI32, MISO39, CS33, IRQ36 |

GPIO27 is separate from the display and touch buses **on the E32R28T**. The display uses HSPI and touch uses VSPI. Do not apply these assignments to an older ESP32-2432S028R board. Use the board's connector labels/orientation diagram to locate connector pin 1; GPIO numbers are not physical ESP32 module pad numbers.

Both builds share the UI and pin map but use **different firmware profiles**. Full uses a battery-fed, AC-coupled AO3400A driver, two TSAL6200 LEDs with 33 ohm resistors, nominal 33% duty, and a GPIO34 voltage guard. Simple uses **one LED + 150 ohm directly from GPIO27**, nominal 50% duty and no battery-only lockout. Select `--profile full` or `--profile simple` when flashing. GPIO35 is input-only; receiver OUT must be 3.3 V logic. Verify receiver lead order. See `HARDWARE_VALIDATION.md` for current limits, charger/switch behavior and commissioning.

Board references: [LCDWiki E32R28T](https://www.lcdwiki.com/2.8inch_ESP32-32E_Display). IR behavior: [IRremoteESP8266](https://github.com/crankyoldgit/IRremoteESP8266/tree/v2.8.6).

## Files and checks

- `src/main.cpp`: display, touch calibration, capture/transmission, USB, NVS, backlight.
- `include/app.h`, `ui.h`: UI state machine and shared renderer.
- `include/core.h`, `storage.h`, `state_store.h`: strict code parser, compact catalog, versioned storage and NVS migration.
- `include/battery.h`: battery readout formatting and 3.0–4.2 V level range.
- `include/input_guard.h`, `power_guard.h`: touch/calibration validation and battery transmit guard.
- `include/power_mode.h`: inactivity policy, backlight levels and wake-gesture suppression.
- `include/board_config.h`, `platformio.ini`: pins and reproducible build versions.
- `tools/native_check.cpp`: catalog integrity and application/storage regression checks; generates screen SVGs.
- `tools/build_catalog.py`, `test_catalog.py`: database conversion and bit-order tests.
- `VALIDATION.md`: actual checks performed and hardware checks still required.

The native check can run with a C++17 compiler from the project directory:

```sh
g++ -std=c++17 -Iinclude tools/native_check.cpp -o native-check
./native-check
python -m unittest discover -s tools -p 'test*.py'
```

The application stores no personal network credentials and makes no network requests. There is no OTA updater. Back up your learned codes as serial text before a flash erase. See `THIRD_PARTY.md` for licenses.
